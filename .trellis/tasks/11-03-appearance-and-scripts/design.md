## 术语

- **发布版本**：发布后不得修改的脚本及依赖内容。
- **启用记录**：用户对具体发布版本的启用确认记录。
- **托管依赖**：纳入发布版本且固定内容的依赖文件。
- **内容摘要**：用于识别源码与托管依赖内容的计算结果。
- **运行代次**：用于区分连续启动操作的标识。
- **挂载点**：脚本放置自定义元素的稳定页面节点。
- **CSP**：浏览器内容安全策略。
- **APP 认证**：现有浏览器应用认证方式。
- **CSRF 防护**：防止伪造跨站请求的校验机制。
- **ESM**：浏览器原生 JavaScript 模块。
- **MIME**：文件内容类型。
- **ACL**：存储对象的访问权限。

## 2. 数据模型

必须使用独立模型保存大段 CSS 和 JavaScript。
不得将源码放入 `Team` 或 `User` 的偏好 JSON。
不得用普通用户响应向工作区广播源码。

| 模型 | 用途 |
| --- | --- |
| `WorkspaceCustomization` | 保存工作区默认配置和发布指向。 |
| `UserCustomization` | 保存个人覆盖和启用记录。 |
| `CustomizationAsset` | 保存私有图片的归属和存储信息。 |
| `CustomizationScriptRevision` | 保存不得修改的脚本发布版本。 |

### 2.1 工作区配置

`WorkspaceCustomization` 的字段包括：

- `teamId`：每个工作区只对应一条记录。
- `backgroundAssetId`：默认背景图的资源 ID。
- CSS 文本。
- 脚本草稿源码。
- 托管模块清单。
- 当前发布版本 ID。
- 每项配置的独立版本标识。

独立版本标识用于检查并发写入。

### 2.2 个人配置

`UserCustomization` 的字段包括：

- 用户与工作区的唯一归属。
- 背景来源：`inherit` 或 `personal`。
- 可以为空的个人 `backgroundAssetId`。
- 个人 CSS 文本。
- 用户启用的发布版本和内容摘要。
- 每项配置的独立版本标识。

个人配置缺失时，背景跟随工作区。
个人配置缺失时，个人 CSS 为空。
个人配置缺失时，脚本不运行。

### 2.3 图片资源

`CustomizationAsset` 的字段包括：

- 资源 ID。
- `teamId`。
- `userId`：图片上传者。
- 工作区或个人归属。
- 私有存储键。
- 校验后的 MIME 和文件大小。
- 资源生命周期状态。
- 时间戳。

### 2.4 脚本发布版本

`CustomizationScriptRevision` 的字段包括：

- 不得修改的版本 ID。
- `teamId`。
- 版本序号。
- 入口源码。
- 顺序固定的托管模块清单。
- 内容摘要。
- `publisherId`。
- `createdAt`。

发布后，不得原地修改源码或依赖。

### 2.5 数据约束

数据库必须约束配置记录的唯一归属。
数据库必须约束资源引用的工作区归属。

脚本发布与启用记录必须用事务和行锁串行写入。
服务端必须在读写前检查访问范围。

更新 JSON 清单时，必须替换整个值。
持久化测试必须重新加载 Sequelize 实例。

迁移后的缺省配置保持继承和空值。
迁移不得自动改变现有用户的外观。
迁移不得自动运行新脚本。

## 3. 接口约定

新增接口遵循现有 RPC 目录结构。
接口必须包含请求校验、策略和响应格式化器。

实现路径为 `server/routes/api/customizations/`。
`index.ts` 导出资源路由。
`customizations.ts` 编排具体接口。
`schema.ts` 定义请求校验。
业务操作位于 `server/commands/customizations.ts`。

脚本草稿写入必须使用 APP 认证。
脚本发布必须使用 APP 认证。
启用记录写入必须使用 APP 认证。
API key 不得代替用户确认启用。
API key 不得发布可执行源码。

服务端必须从认证信息读取操作者和工作区 ID。

| 接口 | 行为与约束 |
| --- | --- |
| `customizations.info` | 返回当前用户的有效外观、个人配置和版本标识。返回有权读取的发布脚本元数据。不得返回管理员草稿或他人的个人配置。 |
| `customizations.workspaceInfo` | 向管理员返回默认配置、当前发布版本和脚本草稿。 |
| `customizations.updateBackground` | 单独保存个人背景或有权修改的工作区背景。检查资源就绪状态、归属和预期字段版本。 |
| `customizations.updateCss` | 单独保存有权修改的 CSS 字段。检查预期字段版本。不得修改发布指向或启用记录。 |
| `customizations.saveScriptDraft` | 只有管理员可以写入草稿。不得修改发布指向或启用记录。 |
| `customizations.publishScript` | 只有管理员可以原子发布源码和依赖快照。内容摘要相同时，不生成新版本。不得因此要求再次启用。 |
| `customizations.enableScript` | 确认当前发布版本 ID 和内容摘要。确认弹窗打开后版本变化时，必须拒绝旧版本确认。 |
| `customizations.disableScript` | 只清除当前用户的启用记录。 |
| `customizations.uploadBackground` | 校验上传范围并限制频率。用 `FileStorage` 接收 multipart 图片。校验和存储成功后才返回就绪资源 ID。 |
| `customizations.background` | 校验资源 ID 的读取权限。返回私有图片流。响应不得缓存或公开重定向。 |

以上接口属于首版实现。
模块读取路径见第 6 节。

路由只编排请求。
跨模型操作必须放入 command。
跨模型操作包括发布、启用确认、图片替换。

必须校验源码大小和请求体大小。
错误必须使用用户可以理解的文案。

每项配置必须单独检查预期版本。
保存 CSS 不得覆盖背景或脚本草稿。
接口测试必须直接验证服务端权限。

## 4. 图片存储与生命周期

必须复用 `FileStorage` 的本地和 S3 存储抽象。
不得复用 `Avatar` 的裁剪或公开 ACL。
不得复用普通附件的工作区级重定向权限。

图片资源使用独立的私有存储命名空间。
图片资源使用独立数据记录。
图片资源不创建普通 `Attachment` 记录。
现有文档附件的访问约定保持不变。

本地 `files.create` 依赖 `Attachment` 记录。
因此，新资源必须使用独立上传接口。

服务端必须校验实际图片字节。
服务端必须校验声明的 MIME。
图片格式为 JPG、PNG、WebP。
文件大小上限不得超过现有上传上限。

存储对象必须使用私有 ACL。
服务端必须按实际内容规范化扩展名和 MIME。
图片上传接口不得接收 URL、HTML 或 SVG。

读取图片前，服务端必须检查个人归属或默认图可见范围。
响应头必须包含 `Cache-Control: private, no-store`。
知道其他用户的个人资源 ID 不代表具有读取权限。
同一浏览器切换账号后，读取权限仍必须生效。

不得为个人图片生成通用签名文件 URL。
通用签名 URL 会形成可以转交的读取凭据。

验证必须覆盖独立图片流接口。
验证必须覆盖本地原始文件接口和 S3 读取路径。
验证必须排除其他路径绕过访问校验的情况。

上传图片与保存配置必须分开。
新上传图片在配置事务提交前保持暂存状态。
配置事务提交前，必须保留原图片引用。

事务提交后，系统调度无引用对象的清理。
清理调度失败不得推翻配置保存结果。
系统必须保留重试清理所需的元数据。

资源清理必须覆盖以下场景：

- 上传失败。
- 配置保存失败。
- 用户删除。
- 工作区删除。
- 图片替换后失去引用。

仍有引用的图片不得按普通导入附件过期删除。

## 6. 发布、托管依赖与启用确认

服务端必须计算整个发布内容的内容摘要。
计算范围包括入口源码和完整的规范化模块清单。
模块清单包含每个模块路径和完整源码。
模块路径按固定顺序排列。
入口源码和清单共同参与一次 SHA-256 计算。
托管依赖字节在该发布版本内不得修改。

只保存远程 URL 不能固定依赖内容。
只保存包版本标签不能固定依赖内容。
本任务不增加 npm 在线安装器或编译器。

原生模块使用应用同源的版本化路径。
实际路径为 `/api/customizations.module/<revisionId>/<modulePath>`。
入口文件名固定为 `entry.js`。

读取模块时，服务端必须检查当前发布版本。
读取模块时，服务端必须检查用户的启用记录。
每个托管依赖请求均必须检查相同条件。

模块路径必须规范化。
模块路径必须限定在发布清单内。
HTTP 响应必须使用私有且不得存储的缓存策略。
服务工作线程不得缓存这些模块路径。
内存中的 ESM 复用必须遵守运行代次约定。
草稿和普通上传文件不得作为可执行模块提供。

加载器使用浏览器模块机制和会话 cookie。
写请求遵循现有 APP 认证与 CSRF 防护。
自定义应用域名只增加所需脚本路径的 CSP 许可。
必须保留现有 nonce。
不得增加 `unsafe-eval`。
不得全局许可普通附件 URL 执行脚本。

发布语法校验依赖解析器时，解析器必须声明为直接依赖。
依赖必须由 Yarn 管理。
不得依赖仅用于开发的包或传递依赖。

### 6.1 脚本生命周期

1. 在运行缓存代码前，读取最新有效配置。
   单独的缓存启用记录不得授权执行。
2. 校验用户、工作区、发布版本和内容摘要。
   全部匹配后才可以加载和启动脚本。
3. 导入发布模块。
4. 校验模块导出的启动函数。
5. 再次检查运行代次。
6. 调用 `activate(context)`。
7. 收集启动函数返回的清理函数。
8. 在启动其他版本前停止当前版本。
9. 中止登记的资源。
10. 调用一次清理函数。
11. 移除控制器持有的模块或启动节点。
12. 丢弃过期的异步结果。

`context` 提供以下辅助能力：

- 稳定挂载点。
- 外观变化事件。
- 导航变化事件。
- `AbortSignal`。
- 资源清理登记。

`context` 不封装或限制 `window`、`document`。

生命周期切换必须串行执行。
运行机制必须抵抗 `StrictMode` 的重复副作用调用。
模块导入延迟完成时，不得启动过期版本。

用户明确恢复同一版本时，可以再次调用启动函数。
不得依赖 ESM 顶层代码重新执行。
普通导航保留运行机制。
普通导航只发出上下文事件。
普通导航不得反复调用同一版本的启动函数。

### 6.2 服务端启用规则

启用记录指向非当前版本时，该记录无效。
发布操作可以保留旧用户记录。
保存草稿不得改变启用记录的有效性。
只修改外观不得改变启用记录的有效性。
过期的确认请求不得启用其他版本。

运行时下载的任意代码不属于托管依赖摘要范围。
界面和文档必须说明这个限制。
不得承诺检测所有远程代码变化。

受信任脚本可以绕过约定的清理接口。
受信任脚本可以修改 React 管理的节点。
运行机制只保证管理自身辅助接口登记的资源。
遵守约定的脚本资源可以随停用清理。

## 7. 更新通知与恢复

工作区更新通过有类型的通知事件发送。
事件只包含配置、版本、发布版本的标识。
工作区事件只发送到对应工作区房间。
个人事件只发送到所属用户房间。

以下时机必须重新读取有权访问的配置：

- 收到配置失效通知。
- WebSocket 完成认证。
- WebSocket 重新连接。
- 页面可见状态变化。

页面可见时，必须补充低频检查。
队列故障不得使旧授权状态无限保留。
通知只能在事务提交后发送。
通知调度失败不得使提交成功的操作失败。

客户端发现发布版本变化时，必须先停止旧脚本。
随后才可以获取新模块。
界面显示 `Enable again`。
不得声称离线浏览器可以立即收到停用通知。
重新连接后，客户端必须先重新校验再恢复执行。

客户端启动时必须解析 `disableCustomizations=1`。
此检查必须早于任何自定义缓存执行。
恢复入口跳过背景、CSS、脚本。
恢复入口必须阻止这些效果再次启动。

恢复状态下，设置编辑器保持可用。
界面提供恢复操作和可以复制的恢复 URL。
移除查询参数不得自动启用新的发布版本。

打印前，暂停辅助接口管理的脚本效果。
打印前，恢复基础打印样式。
打印后，只恢复仍有启用记录的同一版本。
独立登录页、公开分享页和打印路由不挂载运行机制。
停用脚本不撤销脚本对文档的永久修改。

## 8. 设置页面与预览

页面复用现有 `Scene`、`SettingRow`、`Button`、`Input`。
页面复用现有弹窗、策略和延迟加载约定。
新组件必须使用具名导出。
新组件必须包含 JSDoc。
界面字符串必须通过正常翻译提取。
不得手工新增语言文件条目。

个人页面只编辑自己的背景和 CSS。
个人页面可以查看发布脚本并确认启用。
工作区页面必须检查管理员策略。
工作区页面必须区分源码草稿与固定发布版本。

每个页签单独保存以下状态：

- 未保存内容。
- 保存过程。
- 错误。

每个页签必须提供明确的保存操作。
每个页签必须说明继承、叠加或版本关系。
保存一个页签不得提交另一个页签的草稿。

草稿预览必须与主页面隔离。
背景和 CSS 使用独立的小型预览。
替换图片或卸载预览时，必须释放本地图片对象 URL。
不得向预览复制认证信息。

原型的 Shadow DOM 只演示样式隔离。
Shadow DOM 不构成安全沙箱。
生产预览接收任意 CSS 时，必须使用禁用脚本的受控 `iframe`。
普通外观预览不得执行脚本草稿。

原型的图片铺放选择器属于界面建议。
该控件不是额外图片特效的必需项。
未经进一步产品指示，不得增加以下内容：

- 背景模糊。
- 多区域背景。
- 主题打包。

## 9. 部署、回退与执行限制

必须用 Yarn 生成新增式 Sequelize 迁移。
迁移缺省值为空、继承和未确认启用。
部署不得自动改变现有用户外观。
部署不得自动运行脚本。

部署配置必须提供脚本运行总开关。
恢复入口必须独立于总开关。
总开关不得替代用户启用确认。

### 9.1 回退步骤

1. 关闭脚本运行机制。
2. 按故障范围移除自定义样式和背景。
3. 保留修复所需的数据。
4. 回退功能代码。

旧版本应用仍引用资源时，不得删除数据或存储对象。
反向迁移必须在隔离环境验证。
无引用对象清理必须在隔离环境验证。
规划阶段不得在开发者现有数据上执行这些操作。

### 9.2 验证重点

- 其他存储路径绕过个人图片权限。
- 自定义域名下的 CSP。
- ESM 缓存与异步启动竞争。
- CSS 或 DOM 修改与 React 布局的冲突。
- 通知发送失败。
- 不遵守约定的脚本清理限制。

验收标准见 `prd.md`。
执行顺序和检查关卡见 `implement.md`。

## 旧主题管理暂停

用户明确选择同时停用旧页面和全部旧接口。
以下规则替代继续开放旧管理入口的初始设计。

- 删除设置菜单中的旧 Themes 项和懒加载。
- 旧单数和复数地址均精确匹配后跳转。
- `can.update` 为真时，目标为工作区外观页。
- 其余用户的目标为个人外观页。
- 跳转使用 replace，并保留 search 和 hash。
- `disableCustomizations=1` 继续在加载前生效。
- 服务端取消旧 themes 根路由挂载。
- info、list、create、update、delete 均返回标准 404。
- 全局 Theme 组件停止调用旧配色加载 hook。
- Preferences 停止请求旧列表并移除旧配色选择。
- 外观预览停止读取旧偏好和请求旧主题。
- 应用和预览使用内置配色与现有品牌 accent 输入。
- 新背景、CSS 和脚本继续使用 customizations 资源。
- 原主题记录、偏好和缓存不清空。

服务端停用回归直接请求真实根路由。
前端验收记录网络请求，而非只检查菜单。
正常翻译提取可以移除该次删除的三项无用英文键。
其他语言文件和无关英文键必须保留。
