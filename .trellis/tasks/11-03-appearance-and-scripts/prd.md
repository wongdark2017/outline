# 独立外观设置与受信任脚本

## 目标

管理员配置工作区默认背景。
成员可以覆盖个人背景。
外观设置界面提供简体中文。
CSS 和 JavaScript 功能全面暂停，已有数据保留。

## 当前范围优先规则

用户明确选择全面暂停 CSS 和 JavaScript。
以下当前要求替代早期稿中的 CSS 与脚本开放规则。

- 界面只保留背景图设置和背景预览。
- 隐藏 CSS 与 JavaScript 编辑入口。
- 停用全部 CSS 和脚本相关写入接口及模块读取接口。
- 已有工作区 CSS、个人 CSS 与脚本不得继续运行。
- 读取响应保留类型形状，但不返回有效 CSS 或脚本源码。
- 保留数据库中的源码、草稿、发布版本和启用记录。
- 保留工作区背景、个人覆盖、私有图片权限和内置配色模式。
- 简体中文界面沿用用户已有语言选择，不强制修改语言偏好。

早期的 CSS、脚本验收记录只作为历史证据。
当前交付以 R7、R8 和 AC18–AC21 为准。

## 术语

- **发布版本**：发布后不得修改的脚本及依赖内容。
- **启用记录**：用户对具体发布版本的启用确认记录。
- **托管依赖**：纳入发布版本且固定内容的依赖文件。
- **内容摘要**：用于识别源码与托管依赖内容的计算结果。
- **DOM**：浏览器中的页面节点结构。
- **SDK**：脚本调用的辅助接口。
- **恢复入口**：在加载自定义配置前跳过这些配置的入口。

## 需求

### R1 — 独立配置

- 背景图、CSS、JavaScript 必须独立于配色主题。
- 每项配置必须单独编辑。
- 每项配置必须单独保存。
- 切换配色主题时，保留这三项配置。
- 切换配色主题时，保留启用记录。
- 不得引入 ZIP 主题包。
- 不得要求用户制作组合主题包。
- 暂停旧配色主题管理页面。
- 暂停全部 `themes.*` 接口。
- 保留旧主题记录和用户、工作区的配色偏好。
- 当前页面不得读取旧配色缓存或请求旧主题接口。
- 保留内置浅色、深色和跟随系统模式。
- 背景、CSS、脚本继续使用 `customizations.*` 接口。
- 原有 JSON 解析和导出工具可以保留为未挂载代码。

### R2 — 上传背景图与个人覆盖

- 管理员配置工作区默认背景。
- 用户可以上传个人背景图。
- 个人背景图覆盖工作区默认背景。
- 个人覆盖不得影响其他用户。
- 用户可以恢复跟随工作区默认背景。
- 背景设置只接受上传图片。
- 不得提供外部图片 URL 输入框。
- 刷新页面后，必须保留保存结果。
- 重新登录后，必须保留保存结果。
- 保存失败时，必须保留原配置。

### R3 — CSS 叠加

- 管理员配置工作区 CSS。
- 用户可以单独配置个人 CSS。
- 系统必须先加载工作区 CSS。
- 系统必须再加载个人 CSS。
- 样式冲突遵循 CSS 选择器优先级。
- 样式冲突遵循 CSS 重要性规则。
- 后加载的规则不保证覆盖更高优先级的规则。
- 清空个人 CSS 时，保留工作区 CSS。
- CSS 变化不得清除启用记录。

### R4 — 受信任的浏览器脚本

- 脚本必须可以直接访问 `window`。
- 脚本必须可以直接访问 `document` 和 DOM。
- 只提供 SDK 的方式不满足本需求。
- 只在沙箱面板内运行的方式不满足本需求。
- 只有管理员可以发布可执行脚本。
- 成员必须主动确认启用具体的发布版本。
- 工作区默认外观变化不得自动启用脚本。
- 保存脚本草稿时，不得修改当前发布版本。
- 保存脚本草稿时，不得修改启用记录。
- 发布源码或托管依赖变化时，旧启用记录失效。
- 客户端发现新发布版本时，必须停止旧脚本。
- 用户确认启用新版本前，客户端不得运行脚本。
- 只修改背景或 CSS 时，保留启用记录。
- 停用或替换脚本时，必须清理登记的资源。
- 脚本作者负责清理辅助接口之外的副作用。

### R5 — 页面结构

- 个人设置入口为「外观与脚本」。
  英文界面键名为 `Appearance and scripts`。
- 管理员独立入口为「工作区外观与脚本」。
  英文界面键名为 `Workspace appearance and scripts`。
- 两个入口均包含三个独立页签。
  页签为 `Background image`、`CSS`、`JavaScript`。
- 桌面页面并排显示配置区与预览区。
- 窄屏页面在配置区下方显示预览区。
- 界面必须明确显示以下配置状态。

| 界面键名 | 中文含义 |
| --- | --- |
| `Workspace default` | 工作区默认 |
| `Personal override` | 个人覆盖 |
| `Not enabled` | 未启用 |
| `Enabled` | 已启用 |
| `Enable again` | 待重新启用 |

- 个人脚本页必须以只读方式显示发布源码。
- 个人脚本页必须显示发布版本。
- 个人脚本页必须提供启用确认和停用操作。
- 管理员脚本页必须区分保存草稿与发布。
- 外观草稿预览不得自动保存配置。
- 普通设置和外观预览不得自动运行脚本源码。

### R6 — 访问隔离与恢复

- 服务端必须校验工作区权限。
- 服务端必须校验个人配置权限。
- 服务端必须校验直接接口请求和图片访问。
- 隐藏控件不得替代服务端访问校验。
- 个人配置只影响配置作者。
- 不同工作区的配置必须隔离。
- 系统必须在自定义 CSS 和脚本加载前检查恢复入口。
- 恢复入口必须跳过自定义配置及其缓存。
- 恢复状态下，用户必须可以进入设置修复配置。

### R7 — CSS 与 JavaScript 全面暂停

- 设置页面不再挂载 CSS 或 JavaScript 编辑组件。
- 五个 CSS、脚本写入接口和所有模块读取地址均返回标准 404。
- 配置读取与背景保存响应不返回有效 CSS、发布脚本或启用授权。
- 客户端忽略旧响应中的 CSS 和脚本，即使记录原来已经启用。
- 客户端不再创建脚本运行机制或请求作者模块。
- 背景预览不再注入已保存 CSS。
- 数据库保留 CSS、草稿、发布版本、依赖和启用记录。
- 不新增数据库迁移，不删除存储数据。

### R8 — 简体中文外观设置

- 个人与工作区外观设置沿用用户的语言偏好。
- 简体中文覆盖标题、菜单、图片来源和铺放选项。
- 简体中文覆盖上传、保存、恢复、预览和错误提示。
- 预览样例文本使用同一语言。
- 既有其他界面的翻译与其他语言文件保持原值。
- 正常提取英文源键，再验证新增简体中文值与占位参数。

## 执行限制

必须将页面脚本视为当前用户的受信任代码。
脚本拥有当前用户的页面权限。
管理员发布和用户确认不构成安全沙箱。

脚本直接修改 DOM 会增加与 React 渲染冲突的风险。
同步循环可以卡住页面。
异常捕获不能可靠停止同步循环。
恢复入口必须在新页面加载脚本前生效。

入口源码的内容摘要无法检测所有远程代码变化。
技术设计必须区分托管依赖与运行时下载的代码。
技术设计不得承诺检测所有第三方代码变化。
