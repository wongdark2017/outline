> 本指南按《Outline 功能开发指南（中文版）》的格式编写，从头到尾实现一个完整功能：**TikZ 图表**。代码、文件路径、命令和标识符保留英文原文。代码以仓库提交 `4169e8256`（2026 年 10 月 21 日）为准，参照的上游实现是 [siyuan-embed-tikz](https://github.com/YuxinZhaozyx/siyuan-embed-tikz)。

> **状态：** 尚未实现。代码写于提交 `4169e8256`，此后仓库已有变化，开始开发前请先核对。界面设计见 [TIKZ_DESIGN.md](./TIKZ_DESIGN.md)。

## 一个功能如何贯穿 Outline

TikZ 图表是**纯客户端的编辑器功能**：TeX 在编辑者的浏览器里、一个 Web Worker 中编译，结果保存为一张带源码的 SVG 图片。服务端不运行 TeX，不需要迁移、模型、权限策略或新 API —— 它只存储上传的 SVG 附件。

与《文档提醒》自下而上的顺序不同，这个功能按「引擎 → 存储格式 → 编辑器 → 界面」构建：

1. **静态引擎资源**（`server/static/tikzjax/`）—— WASM TeX、格式文件、宏包、字体，全部随 Outline 发布，完全离线。
2. **Worker 封装**（`app/editor/lib/tikz/`）—— 启动 worker、编译、超时终止。
3. **SVG 后处理** —— 把 TikZ 源码写进 SVG 的 `<metadata>`，格式与思源插件相同。
4. **内容安全策略**（`server/middlewares/csp.ts`）—— 允许 WebAssembly。
5. **图片来源标记**（`shared/editor/lib/FileHelper.ts`）—— `ImageSource.Tikz`，让粘贴或上传的 TikZ SVG 也能再次编辑。
6. **编辑器扩展**（`app/editor/extensions/Tikz.tsx`）—— `insertTikz` / `editTikz` 命令，以及承载对话框的 widget。
7. **编辑对话框**（`app/editor/components/TikzEditor.tsx`）—— 代码、实时预览、错误信息。
8. **菜单入口** —— 斜杠菜单 `/tikz`、图片工具栏、灯箱。
9. **测试**与代码放在一起。

### 行为

- 用户输入 `/tikz`，打开对话框，左侧写 TikZ 代码，右侧在停止输入约 600 ms 后显示预览。代码可以是 tikzpicture 片段，也可以是整段粘贴的 .tex 文档（第 10 步）。
- 点击「保存」，SVG 作为附件上传，文档中插入一个 `source: "tikz"` 的图片节点。
- 选中这张图片，工具栏或灯箱中出现「编辑 TikZ」，对话框从 SVG 中读回源码。
- 读者、分享页面、HTML/PDF 导出看到的都是普通图片，不加载 TeX 引擎。
- 从思源笔记导出的 TikZ SVG 上传后同样可以编辑，反之亦然。

## 确定功能放在哪里

这是一个**编辑器扩展**，但它不新增节点类型：复用已有的 `image` 节点和它的 `source` 属性，与 diagrams.net 的做法一致。开始前对照这三个现有实现：

| 我们需要的 | 仓库中的蓝本 | 参考什么 |
| --- | --- | --- |
| 图片 + 可再编辑的源数据 | `shared/editor/extensions/Diagrams.ts` | 上传文件、按 `src` 找回节点、`ImageSource.DiagramsNet` |
| 在编辑器上层显示 React 界面 | `app/editor/extensions/FindAndReplace.tsx` | 用 MobX `@observable` 控制的 `widget()` |
| 按需加载的重型渲染器 | `shared/editor/extensions/Mermaid.ts` | `await import("mermaid")` 懒加载，不进入主包 |

为什么扩展放在 `app/editor/extensions/` 而不是 `shared/editor/extensions/`：对话框需要 `app/components/Modal.tsx`，而 `shared/` 不能依赖 `app/`。`FindAndReplace`、`BlockMenu` 等带界面的扩展都在 `app/` 侧，并通过 `withUIExtensions` 注册。

在哪里执行：

- **在浏览器 worker 中：** TeX 编译 —— CPU 密集、可能死循环，必须离开主线程并可以被终止。
- **在主线程：** SVG 后处理、上传、更新文档 —— 都很快。
- **在服务端：** 只有附件存储，走现有的 `attachments` 接口，无需新代码。

这个功能会加入约 11 MB 的静态资源并放宽 CSP。如果要提交到上游，先在 GitHub issue 中和维护者确认这两点；只在自己的 fork 中使用则不受影响。

## 第 0 步 —— 准备分支、引擎和许可证

先开一个干净的分支。工作区里有与本功能无关的未提交改动（`Makefile`、`shared/validations.ts`、提醒迁移），不要把它们混进来：

```bash
git switch -c feat/tikz
yarn add threads @codemirror/state @codemirror/view @codemirror/commands codemirror-lang-latex
```

然后从插件仓库取出引擎。整个 `src/libs/tikzjax/` 目录就是一套自包含的 TikZJax 构建：

```bash
git clone --depth 1 https://github.com/YuxinZhaozyx/siyuan-embed-tikz /tmp/siyuan-embed-tikz
mkdir -p server/static/tikzjax
cp -R /tmp/siyuan-embed-tikz/src/libs/tikzjax/. server/static/tikzjax/
```

| 文件 | 大小 | 作用 |
| --- | --- | --- |
| `core.dump.gz` | 约 6 MB | 预加载了 LaTeX 与 TikZ 的 TeX 格式文件 |
| `run-tex.js` | 约 600 KB | Worker 脚本，通过 `threads` 暴露 `load()` 和 `texify()` |
| `tex.wasm.gz` | 约 120 KB | 编译成 WebAssembly 的 TeX 引擎 |
| `tex_files/` | 293 个文件 | 按需加载的宏包（`amsmath.sty.gz` 等） |
| `fonts/`、`fonts.css` | — | Computer Modern 等 `.woff2` 字体 |

`server/static/` 是 Vite 的 `publicDir`（见 `vite.config.ts`），里面的文件在开发和生产环境都以 `/static/...` 提供，不经过打包。

### 许可证

在继续之前确认三方的许可证：

- **思源插件：** MIT。复制时保留版权声明。
- **TikZJax（`drgrice1/tikzjax`）：** LPPL 1.3c。它允许再发布，但对修改后的文件有改名等要求 —— 我们不修改这些文件，只是原样提供。
- **TeX 宏包与字体：** 各有自己的许可证（多为 LPPL 或 SIL OFL）。

在 `server/static/tikzjax/` 中放一个 `LICENSES.md`，列出来源和各自的许可证。如果要提交到上游，这一点需要维护者确认（Outline 使用 BSL 许可证）。

## 第 1 步 —— 静态引擎资源

第 0 步复制的文件已经可以访问了：开发环境由 Vite 从 `publicDir` 提供，生产环境由 `yarn build` 复制到 `build/app/`，再由 `server/routes/index.ts` 中的 `/static/{*path}` 路由提供。这一步只需要用一个常量固定它们的地址。

新建 `app/editor/lib/tikz/constants.ts`：

```typescript
/**
 * Same-origin URL of the bundled TikZJax engine. Workers must be loaded from
 * the page's own origin, so this deliberately ignores CDN_URL.
 *
 * The /static route serves files with a one year immutable cache, so bump the
 * folder name (e.g. tikzjax-2) whenever the engine files are replaced.
 */
export const TIKZJAX_URL = `${window.location.origin}/static/tikzjax`;

/** Renders taking longer than this are aborted and the worker terminated. */
export const RENDER_TIMEOUT_MS = 10_000;

/** MIME type of the script element that carries the TikZ source in the SVG. */
export const TIKZ_SOURCE_TYPE = "text/x-tikz";
```

启动开发服务器后验证：

```bash
curl -I https://local.outline.dev:3000/static/tikzjax/tex.wasm.gz
curl -I https://local.outline.dev:3000/static/tikzjax/tex_files/amsmath.sty.gz
```

两条都应返回 `200`。

### 容易出错的地方

- **不要用 `env.CDN_URL`。** `vite.config.ts` 的 `base` 在配置了 CDN 时会指向 CDN，但 `new Worker()` 只接受同源脚本，CSP 的 `workerSrc` 也只有 `'self'`。
- **缓存。** 生产环境的 `/static` 文件带 `immutable`，而这些文件名没有哈希。更换引擎时不改目录名，用户会一年内都拿到旧文件。
- **不要 `import` 这些文件。** 它们只通过 URL 加载，否则 Vite 会把 11 MB 打进主包。
- **`.gz` 文件是原始字节。** `run-tex.js` 自己解压；反向代理不能给它们加 `Content-Encoding: gzip`，否则浏览器会提前解压，引擎加载失败。

## 第 2 步 —— Worker 封装

这一步移植插件 `src/tikz.ts` 中的 `compileTikZ()` 和 `initializeWorker()`，并补上它缺少的超时。`run-tex.js` 通过 `threads` 库暴露两个方法：`load(urlRoot)` 下载 WASM 和格式文件，`texify(source, options)` 返回 SVG 字符串。

新建 `app/editor/lib/tikz/renderTikz.ts`：

```typescript
import { spawn, Thread, Worker } from "threads";
import type { ModuleThread } from "threads";
import { RENDER_TIMEOUT_MS, TIKZJAX_URL } from "./constants";
import { embedSource } from "./svg";

/** The API exposed by run-tex.js. */
type TexWorker = {
  load(urlRoot: string): Promise<void>;
  texify(input: string, options: { embedFonts: boolean }): Promise<string>;
};

export type RenderResult =
  | { ok: true; svg: string }
  | { ok: false; error: string };

/**
 * Compiles TikZ source to an SVG in a fresh web worker. A new worker is used
 * for every render, as TeX state is not reset between runs.
 *
 * @param source - the TikZ source, usually a tikzpicture environment.
 * @param signal - aborts the render and terminates the worker.
 * @returns the SVG with the source embedded, or the TeX error message.
 */
export async function renderTikz(
  source: string,
  signal?: AbortSignal
): Promise<RenderResult> {
  let worker: ModuleThread<TexWorker> | undefined;
  let aborted = false;
  let timer: ReturnType<typeof setTimeout> | undefined;

  const run = async () => {
    const spawned = await spawn<TexWorker>(
      new Worker(`${TIKZJAX_URL}/run-tex.js`)
    );
    if (aborted) {
      await Thread.terminate(spawned);
      throw new Error("Render aborted");
    }
    worker = spawned;
    await worker.load(TIKZJAX_URL);
    return worker.texify(source, { embedFonts: true });
  };

  const timeout = new Promise<never>((_resolve, reject) => {
    timer = setTimeout(() => {
      aborted = true;
      reject(new Error(`Render took longer than ${RENDER_TIMEOUT_MS / 1000}s`));
    }, RENDER_TIMEOUT_MS);
    signal?.addEventListener("abort", () => {
      aborted = true;
      reject(new Error("Render aborted"));
    });
  });

  try {
    const svg = await Promise.race([run(), timeout]);
    return { ok: true, svg: embedSource(svg, source) };
  } catch (err) {
    return {
      ok: false,
      error: err instanceof Error ? err.message : String(err),
    };
  } finally {
    clearTimeout(timer);
    if (worker) {
      await Thread.terminate(worker);
    }
  }
}
```

`embedSource()` 在第 3 步实现。

### 设计说明

- **每次渲染一个新 worker。** 与插件相同。TeX 运行后会留下全局状态，重用 worker 会让上一张图的定义污染下一张。第二次以后的 `load()` 走 HTTP 缓存，主要开销是解压 6 MB 的格式文件。
- **超时一定要终止 worker。** `\def\x{\x}\x` 这样的代码会让 TeX 永远不返回。`Promise.race` 只是不再等待，真正释放 CPU 的是 `finally` 里的 `Thread.terminate`。`aborted` 标志处理「超时时 worker 还没启动完」的情况。
- **不要在模块顶层启动 worker。** 只在用户打开 TikZ 对话框后调用 `renderTikz()`，读者永远不会下载引擎。对话框用 `React.lazy` 加载（第 7 步），这个文件和 `threads` 也不会进入主包。

## 第 3 步 —— SVG 后处理与源码元数据

源码以和思源插件完全相同的形式放在 SVG 开头，这样两边导出的图片可以互相编辑：

```xml
<svg ...>
  <metadata><script type="text/x-tikz">\begin{tikzpicture} ... \end{tikzpicture}</script></metadata>
  ...
</svg>
```

新建 `app/editor/lib/tikz/svg.ts`：

```typescript
import { TIKZ_SOURCE_TYPE } from "./constants";

const SVG_NS = "http://www.w3.org/2000/svg";

/**
 * Removes executable content and stores the TikZ source in the SVG's
 * metadata, in the same format as the siyuan-embed-tikz plugin.
 *
 * @param svg - the SVG markup produced by TeX.
 * @param source - the TikZ source to embed.
 * @returns the serialized SVG.
 */
export function embedSource(svg: string, source: string): string {
  const doc = new DOMParser().parseFromString(svg, "image/svg+xml");
  const root = doc.documentElement;
  if (root.nodeName !== "svg" || doc.querySelector("parsererror")) {
    throw new Error("TeX did not produce an image");
  }

  root.querySelectorAll("script").forEach((el) => el.remove());
  for (const el of [root, ...root.querySelectorAll("*")]) {
    for (const attr of Array.from(el.attributes)) {
      const value = attr.value.trim().toLowerCase();
      if (
        attr.name.toLowerCase().startsWith("on") ||
        value.startsWith("javascript:")
      ) {
        el.removeAttribute(attr.name);
      }
    }
  }

  const metadata = doc.createElementNS(SVG_NS, "metadata");
  const script = doc.createElementNS(SVG_NS, "script");
  script.setAttribute("type", TIKZ_SOURCE_TYPE);
  script.textContent = source;
  metadata.appendChild(script);
  root.insertBefore(metadata, root.firstChild);

  return new XMLSerializer().serializeToString(root);
}

/**
 * Reads the TikZ source back out of an SVG created by embedSource or by the
 * siyuan-embed-tikz plugin.
 *
 * @param svg - the SVG markup.
 * @returns the TikZ source, or undefined if the SVG has none.
 */
export function extractSource(svg: string): string | undefined {
  const doc = new DOMParser().parseFromString(svg, "image/svg+xml");
  return (
    doc.querySelector(`script[type="${TIKZ_SOURCE_TYPE}"]`)?.textContent ??
    undefined
  );
}
```

### 为什么这样是安全的

- `type="text/x-tikz"` 不是脚本类型，浏览器不会执行它。
- Outline 用 `<img>` 显示图片，`<img>` 中的 SVG 不运行任何脚本。
- 直接打开附件地址时，`server/storage/files/BaseStorage.ts` 故意没有把 `image/svg+xml` 列入 `safeInlineContentTypes`，所以它会以 `Content-Disposition: attachment` 下载，而不是在当前域名下渲染。
- 我们仍然删除其他 `<script>` 和 `on*` 属性，因为用户也可以上传自己伪造的「TikZ」SVG。

### 容易出错的地方

- **不要用 `innerHTML` 解析。** 插件用 HTML 解析器加 `escapeHTML`；这里用 XML 解析器和 `XMLSerializer`，它们自己处理 `&`、`<` 的转义。两种读法都能还原对方写入的源码，第 11 步的测试会验证这一点。
- **不要删除 `<style>` 或 `@font-face`。** `embedFonts: true` 把字体嵌在里面，删掉后公式会变成错误字体。

## 第 4 步 —— 内容安全策略（CSP）

Outline 的 CSP 在 `server/middlewares/csp.ts` 中生成，由 `server/services/web.ts` 对所有响应启用。目前 `scriptSrc` 中没有 `'wasm-unsafe-eval'`，浏览器会拒绝编译 `tex.wasm`，控制台报 `CompileError: WebAssembly.instantiate(): Refused to compile or instantiate WebAssembly module`。

在 `scriptSrc` 的 `uniq([...])` 中加一项：

```typescript
          scriptSrc: uniq([
            ...scriptSrc,
            `${ctx.host}/static/`,
            ...(options?.extraScriptSrc ?? []),
            ...(ctx.state.cspScriptSrc as string[]),
            // Allows the TikZ editor to compile its TeX engine. This permits
            // WebAssembly compilation only, not JavaScript eval().
            "'wasm-unsafe-eval'",
            env.DEVELOPMENT_UNSAFE_INLINE_CSP
              ? "'unsafe-inline'"
              : `'nonce-${ctx.state.cspNonce}'`,
          ]),
```

其他指令不用改：

| 指令 | 当前值 | 为什么够用 |
| --- | --- | --- |
| `workerSrc` | `'self'` | `run-tex.js` 来自同源的 `/static/tikzjax/` |
| `connectSrc` | `*` | worker 用 `fetch` 下载 `.gz` 文件 |
| `imgSrc` | `* data: blob:` | 预览用 `data:` URL 显示 SVG |

### 容易出错的地方

- **开发环境可能掩盖问题。** 开发时 `/static` 由 Vite 提供，worker 脚本的响应可能没有 CSP 头。一定要在 `yarn build && yarn start` 的生产构建上再试一次。
- **不要用 `'unsafe-eval'`。** 它会同时放开 JavaScript 的 `eval()`，范围太大。
- **反向代理。** 如果你的部署在 nginx 等代理上另外设置了 CSP，那里也要加 `'wasm-unsafe-eval'`。

## 第 5 步 —— ImageSource 与 SVG 识别

`image` 节点已经有一个 `source` 属性，用来标记 diagrams.net 图片。它会被写进 Markdown 标题（`![](…svg "source=diagrams.net")`），`shared/editor/nodes/Image.tsx` 用 `source=(\S+)` 读回，所以新增一个值不需要改解析代码。

在 `shared/editor/lib/FileHelper.ts` 中：

```typescript
export enum ImageSource {
  DiagramsNet = "diagrams.net",
  Tikz = "tikz",
}
```

然后扩展 `getImageSourceAttr()`，并在 `isDiagramsNetSvg()` 旁边加一个私有方法。上传或粘贴图片时，这个方法已经被调用，所以从思源导出的 TikZ SVG 会自动标记为可编辑：

```typescript
  static async getImageSourceAttr(
    file: File
  ): Promise<ImageSource | undefined> {
    if (await this.isDiagramsNetImage(file)) {
      return ImageSource.DiagramsNet;
    }
    if (await this.isTikzImage(file)) {
      return ImageSource.Tikz;
    }
    return undefined;
  }

  /**
   * Checks if an SVG file carries TikZ source in a
   * <script type="text/x-tikz"> element, as written by the TikZ editor and
   * the siyuan-embed-tikz plugin.
   *
   * @param file The image file to check
   * @returns True if the file contains embedded TikZ source
   */
  private static async isTikzImage(file: File): Promise<boolean> {
    if (file.type !== "image/svg+xml") {
      return false;
    }
    try {
      const text = await file.text();
      return /<script[^>]*type=["']text\/x-tikz["']/.test(text);
    } catch {
      return false;
    }
  }
```

这里用字符串匹配而不是 `extractSource()`，因为 `shared/` 不能导入 `app/` 的代码，而且这里只需要判断有无，与 `isDiagramsNetSvg()` 的做法一致。

## 第 6 步 —— 编辑器扩展

扩展提供两个命令，并用一个 widget 挂载对话框。菜单项的 `name` 就是命令名，所以第 8 步的菜单只需要写 `name: "insertTikz"` 和 `name: "editTikz"`。

### 共用的查找函数 —— `shared/editor/queries/findImageNodeBySrc.ts`

上传是异步的，等它完成时文档可能已经变了，所以不能记住位置，而是按 `src` 重新找节点。这是 `Diagrams.ts` 中 `findImageNodeBySrc()` 的做法，把它提取出来共用：

```typescript
