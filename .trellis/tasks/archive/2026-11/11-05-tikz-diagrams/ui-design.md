## 1. 设计结论

功能入口放在现有编辑器中。
编辑者主要使用一个 TikZ 对话框。
文档中保存的结果继续显示为普通图片。

| 界面位置    | 加入功能后的变化                                  |
| ----------- | ------------------------------------------------- |
| 斜杠菜单    | diagrams.net 后增加「TikZ 图表」。                |
| TikZ 对话框 | 增加代码区、状态栏、预览区、错误区和保存操作。    |
| 图片工具栏  | 对 TikZ 图片增加「编辑 TikZ」，隐藏「替换图片」。 |
| 灯箱        | 对 TikZ 图片增加编辑入口。                        |
| 读者视图    | 展示普通图表图片，不显示创建和编辑入口。          |

页面使用仓库默认的紫色强调色。
侧栏保持浅灰，正文和预览保持清晰的阅读背景。
编辑对话框的视觉重点是代码和对应预览。

## 2. 正常编辑时的整体界面

![加入 TikZ 后的桌面编辑对话框](/root/outline/.trellis/tasks/11-05-tikz-diagrams/ui/02-editor.png)

### 2.1 区域说明

| 区域       | 内容                                 | 操作规则                                     |
| ---------- | ------------------------------------ | -------------------------------------------- |
| 页眉       | 「TikZ 图表」和关闭按钮。            | 关闭后丢弃未保存修改。                       |
| 左侧代码区 | 行号、LaTeX 语法高亮和原始源码。     | 新建时显示默认模板；编辑时显示图片中的源码。 |
| 左侧状态栏 | 输入模式、库、跳过的宏包和字体提示。 | 内容较长时横向滚动，不挤压代码区。           |
| 右侧预览区 | 白底 SVG 图表。                      | 展示最后一次成功预览。                       |
| 统一错误区 | 固定中文文案和相关 TeX 原文。        | 位于两栏下方、操作按钮上方。                 |
| 页脚       | 「取消」和「保存」。                 | 只有当前预览有效且没有错误时，才允许保存。   |

### 2.2 尺寸与滚动

| 项目         | 设计规则                                     |
| ------------ | -------------------------------------------- |
| 桌面视口示例 | `1440 × 1000` CSS 像素，截图 DPR 为 1。   |
| 对话框宽度   | `min(1100px, 90vw)`。                      |
| 桌面列比例   | 两栏等宽，间距为 `16 px`。                 |
| 两栏高度     | 以 `60vh` 为目标，在可用高度内收缩。       |
| 内容边距     | 桌面左右 `24 px`；窄屏左右 `14 px`。     |
| 代码字号     | 桌面示意为 `13 px`，窄屏示意为 `12 px`。 |
| 源码长行     | 在代码区内横向滚动，不拉宽页面。             |
| 源码较多     | 代码区独立纵向滚动，状态栏固定在面板底部。   |
| 错误区       | 最高 `120 px`，超出后独立滚动。            |
| 底部操作     | 保留独立空间，不随代码或错误内容滚出视口。   |

错误出现时，两栏让出错误区所需的高度。
对话框位置和底部按钮保持稳定。

### 2.3 当前组件的适配要求

现有 Modal 使用 `640 px` 内容宽度和 `65vh` 内容高度限制。
现有外层还使用 `75vw` 宽度和 `25vh` 顶部间距。
因此，仅设置对话框的最大宽度不足以保证新布局。

实现时必须在 TikZ 对话框范围内适配内部宽高和滚动。
必须验证两栏、错误区和底部操作同时可见。
原型中的布局用于表达目标，不代表现有 Modal 已满足这些条件。

图中展示未筛选菜单的图表区域。

| 项目       | 规定                                                         |
| ---------- | ------------------------------------------------------------ |
| 菜单标题   | 「TikZ 图表」。                                              |

## 4. 对话框状态

### 4.1 状态与控件

| 状态               | 代码与状态栏         | 预览区                                 | 「保存」                 |
| ------------------ | -------------------- | -------------------------------------- | ------------------------ |
| 新建后等待输入停顿 | 显示默认模板。       | 首次无预览。                           | 禁用。                   |
| 加载引擎或渲染中   | 可以继续输入。       | 显示「正在渲染…」；存在旧预览时保留。 | 禁用。                   |
| 当前预览就绪       | 保留当前源码。       | 显示与当前源码对应的预览。             | 没有错误时启用。         |
| 编译错误或超时     | 保留源码和错误说明。 | 保留上一张成功预览。                   | 禁用。                   |
| 保存中             | 保留本次提交内容。   | 保留本次提交的预览。                   | 禁用，显示「保存中…」。 |
| 保存失败           | 保留源码和预览。     | 保留上一张成功预览。                   | 错误存在时禁用。         |
| 已有源码读取失败   | 不填入默认模板。     | 不生成新的默认图表。                   | 禁用。                   |

任意状态均允许取消或关闭。
用户主动取消时，不显示编译失败提示。

渲染、保存和超时状态截图：
[渲染中](ui/12-loading.png)、[保存中](ui/13-saving.png)、[保存失败](ui/14-save-error.png)、[渲染超时](ui/15-timeout.png)。

### 4.2 缺少宏包时

![缺少宏包时的错误位置和保留预览](/root/outline/.trellis/tasks/11-05-tikz-diagrams/ui/03-error.png)

示例中，原始源码第 3 行引用 `pgf-pie`。
错误区显示以下固定文案：

> 第 3 行：渲染引擎不支持宏包 pgf-pie。请移除该声明或改用支持的 TikZ 库。

文案下方显示相关 TeX 错误原文。
状态栏同时显示「pgf-pie 不可用」。
右侧保留上一张成功预览，不能将它作为当前源码的结果保存。

第 3 行的底色仅用于示意原始声明位置。
实际错误定位必须使用原始源码行号，不得使用改写后日志的行号。

### 4.3 已有图片的源码加载失败

![源码读取失败时的界面](/root/outline/.trellis/tasks/11-05-tikz-diagrams/ui/09-source-error.png)

固定文案为：

> 图表源码加载失败。原图未修改，请稍后重新打开。

代码区显示「源码未加载」。
不得用默认模板代替无法读取的源码。
原图保持不变，「保存」禁用。
用户可以关闭对话框。

### 4.4 异常文案的唯一来源

全部异常文案以 [PRD 第 3.2.5 节](prd.md#325-异常固定文案与显示规则)为准。
本设计稿只展示选定场景，不另设一套异常文案。

- 固定提示使用主题错误色。
- TeX 诊断使用等宽字体。
- 整个区域最高 `120 px`，超出后滚动。
- 不使用 Toast 或系统警告框替代错误区。
- 未找到原始行号时，使用 E02-F。
- 自动跳过 CJK 字体设置使用状态栏提示，不作为编译错误。

## 5. 保存后的图片与再次编辑

### 5.1 图片工具栏

![文档中的 TikZ 图片和工具栏](/root/outline/.trellis/tasks/11-05-tikz-diagrams/ui/04-image.png)

工具栏沿用当前代码中的顺序：

```text
左对齐 · 居中 · 右对齐 · 通栏
→ 尺寸 → 编辑 TikZ → 下载 → 删除 → 创建链接 → 评论
```

「编辑 TikZ」位于当前图表编辑操作附近。
该入口使用铅笔图标；图中展开文字便于评审识别。
实际实现可以沿用现有图标按钮和 Tooltip。

当前工具栏中的尺寸、链接和评论能力保留。
TikZ 图片不显示普通图片的「替换图片」菜单。
再次编辑时，读取 SVG 中的原始源码。
保存后在原位置替换图片，并保留其普通图片行为。

### 5.2 灯箱入口

![灯箱中的 TikZ 编辑入口](/root/outline/.trellis/tasks/11-05-tikz-diagrams/ui/05-lightbox.png)

灯箱继续使用当前放大、缩小、复制链接和下载操作。
TikZ 图片额外提供铅笔编辑入口。
关闭灯箱后，再打开 TikZ 对话框。
两个模态界面不得同时争抢焦点。

### 5.3 读者视图

![读者只查看普通图表图片](/root/outline/.trellis/tasks/11-05-tikz-diagrams/ui/11-readonly.png)

读者看到普通图片。
界面不显示 TikZ 创建和编辑入口。
阅读、分享和导出不加载 TeX 引擎。

## 6. 暗色模式

![暗色主题中的编辑对话框](/root/outline/.trellis/tasks/11-05-tikz-diagrams/ui/06-dark.png)

| 区域                | 暗色显示规则                            |
| ------------------- | --------------------------------------- |
| 文档与侧栏          | 使用当前暗色主题。                      |
| 对话框与代码区      | 使用暗色背景、浅色文字和可辨识的边框。  |
| 预览区              | 始终为白色，图表保持浅色渲染。          |
| 文档中的 TikZ 图片  | 使用 `invert(1) hue-rotate(180deg)`。 |
| 普通图片            | 不应用 TikZ 滤镜。                      |
| HTML 导出与打印/PDF | 保留浅色输出。                          |

暗色文档图片效果见[暗色图片示意](ui/10-dark-image.png)。
显式颜色在滤镜下显示为近似颜色。

| 操作           | 目标行为                     | 当前验证范围                       |
| -------------- | ---------------------------- | ---------------------------------- |
| 打开编辑       | 焦点位于代码区。             | 原型中验证初始焦点。               |

## 10. 验证记录与交付文件

### 10.1 已执行的原型检查

[浏览器检查记录](ui/capture.json)包含 16 张截图和 119 项检查。
检查范围为：

- 页面身份、逻辑视口和 DPR。
- 页面横向溢出。
- 保存按钮和页脚的位置。
- 有效与无效预览状态下的保存按钮状态。
- 错误区位置和 `120 px` 高度限制。
- 初始代码区焦点。
- 暗色对话框中的白色预览背景。
- 源码读取失败时不填入默认模板。
- 只读视图不出现 TikZ 编辑入口。
- 图片和灯箱的编辑入口。
- 设计原型的编辑、保存中和 Esc 状态切换。
- 原型没有向外部服务发送请求。

这些检查针对设计原型。
真实编译、附件上传、协同编辑和生产 CSP 未验证。
