# 技术设计：代码块语言搜索

## 职责划分与数据流

`shared/editor/lib/code.ts` 统一管理语言元数据和搜索排序。在语言定义中增加 `keywords?: string[]` 字段，为实施方案中的 38 种语言填入关键词。

新增导出纯函数 `searchCodeLanguages(query, frequent)`。它读取语言列表，排除 `alias: true` 的兼容别名，每种语言最多返回一条匹配结果。结果包含语言 ID、显示名称，以及可选的名称命中区间或命中的关键词。搜索函数不修改语言使用记录。

编辑器中的调用顺序为：

`SelectionToolbar` → `codeMenuItems` → `ToolbarMenu` → `CodeLanguagePicker` → 现有的 `commands.code_block({ language })`。

语言菜单项使用现有的 `content` 字段承载选择器。`ToolbarMenu` 在检查图标、渲染普通菜单项之前，先处理顶层自定义内容。只读模式仍只显示语言名称。

`CodeLanguagePicker` 从当前节点读取语言，在组件内部管理打开状态、查询词和高亮项，并在打开时读取现有的常用语言列表。

## 搜索与排序规则

对查询词、语言名称和关键词统一执行 `deburr`、去首尾空格和转小写。归一化后的查询词为空时，搜索函数返回空数组，由选择器展示分组列表。

每种语言取其能达到的最高优先级，按以下六档匹配：

1. 名称或关键词完全相同。
2. 名称开头匹配。
3. 关键词开头匹配。
4. 名称中的词首匹配，前一个字符为空格、`-`、`+`、`#`、`.` 或 `/`。
5. 名称任意位置包含查询词。
6. 关键词任意位置包含查询词。

单字符查询只使用前三档。先按匹配档位排序；同档内，常用语言按常用列表中的顺序靠前，其余语言保持原语言列表顺序。

名称命中时返回原始显示名称中的命中区间。若关键词匹配的档位优于名称匹配，或名称没有命中，则返回命中的最佳关键词。语言 ID 和显示名称保持现有定义。单元测试显式传入 `frequent` 数组，避免依赖本地存储。

## 选择器界面与交互

使用 `cmdk@^1.1.1`，设置 `shouldFilter={false}` 和 `loop`。由搜索函数完成过滤、排序，由 cmdk 提供方向键导航、鼠标高亮、回车选择和无障碍状态。触发按钮沿用工具栏中的 `ToolbarButton`、`Label` 和 `ExpandedIcon` 样式。

语言触发按钮通过局部样式设置 `flex: 0 0 auto` 和 `white-space: nowrap`，按文字及图标的实际宽度布局，避免 `Splunk SPL` 等带空格的名称换行或挤压箭头。

打开时高亮当前语言。查询词变化后，高亮第一个可见结果。重新打开时清空查询词，并恢复当前语言的高亮。桌面端使用方向键导航时，焦点始终留在搜索框。

查询词为空时，先展示「最近使用」分组，再展示其余非别名语言；没有使用记录时不显示「最近使用」。有查询词时展示不分组的结果列表，将名称命中部分加粗；依靠关键词命中时，在右侧用等宽字体显示该关键词。当前语言显示勾选标识。

搜索框有内容时显示清空按钮。没有匹配结果时显示包含查询词的提示，以及扩展名示例。界面不包含设计稿底部的快捷键提示栏。

桌面端复用现有 `Popover`，宽度约 280px，使用 `menuBackground` 和 `menuShadow`，选项高 32px，高亮项使用 `accent` 底色。移动端复用现有 `Drawer`，选项高 48px，搜索框字号 16px，滚动区域考虑底部安全区，打开时不自动聚焦搜索框。两种界面都提供可供辅助技术读取的名称。

有查询词时，Esc 先清空查询词；查询词为空时，Esc 关闭选择器。输入法组合期间按回车不得触发选择。

选中后关闭选择器。若选中的 ID 与当前语言相同，则不调用 `code_block`，避免现有命令把代码块切换为段落。选择其他语言时，沿用原工具栏的做法，在命令执行前后调用 `closeHistory`，并在浮层关闭后恢复编辑器焦点。

选择器通过 Portal 渲染到工具栏 DOM 之外，点击列表时仍需保留编辑器选区。桌面列表阻止 `mousedown` 的默认行为，让输入框保留焦点；如果仍会触发选区重置，则在 `SelectionToolbar` 的外部点击判断中，仅放行来自语言选择器的事件。

## 依赖与翻译

通过 Yarn 安装 `cmdk@^1.1.1`，随后运行 `yarn dedupe '@radix-ui/*'` 和 `yarn install`。带引号的范围将去重限定在 Radix 包。检查锁文件，记录实际升级的版本，并通过 `yarn dedupe --check '@radix-ui/*'` 检查是否仍有可合并的重复依赖。

本次去重并升级 Radix 是用户已确认的决定。这些依赖也用于现有对话框、弹出层、菜单、提示框和焦点管理，因此需要回归验证这些控件。

通过 `yarn build:i18n` 提取新增英文键，再将实施方案中已确认的七条中文翻译应用到 `zh_CN`。检查翻译键集合和插值占位符，保留其他条目。英文源文案由提取流程生成，不手动添加到英文翻译文件。

## 兼容性、验证与回滚

本功能不涉及数据库结构、API、文档存储格式或语言 ID 的变化。现有代码块和 `mermaidjs` 兼容别名继续使用原有解析逻辑。

使用指定文件的 Vitest 测试验证搜索规则，再运行 TypeScript 检查以及改动文件的 lint 和格式检查。通过浏览器验证桌面端和模拟移动端的交互。真机键盘遮挡情况需要手机验证；若当前环境无法完成，明确记录为未验证项。

回滚时撤销本功能的代码及依赖锁文件改动即可，不需要数据迁移。
